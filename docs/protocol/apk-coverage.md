# Retained APK evidence coverage

2026-10-13. Generated by `cargo run -p xtask -- apk-coverage` into
[apk-coverage.json](apk-coverage.json); `--check` fails when the committed report
is stale. Rerun it after adding or regenerating any bundle under
[apk/](apk/README.md).

## What it measures

Only the committed research bundles: each bundle's `manifest.json` (release and
APK hash) and `targets.json` (topic → class/method → Rust files). It does not
count [REA envelopes](rea/), APK classes cited in code comments or protocol
documents, or anything never exported. "Uncited" therefore means *no retained
bundle topic names this file*, not *no APK evidence exists for it*.

## Findings (2026-10-13)

| Release | Bundles | Topics |
|---|---|---|
| **2.26.36.75** (pinned default profile) | **0** | 0 |
| 2.26.37.70 | 1 | 21 |
| 2.26.37.71 | 166 | 2,126 (1,962 distinct topic names overall) |

- **The pinned release has no retained code bundle.** Every behaviour the
  default profile relies on is evidenced from the comparison builds, which is
  why the default `registration begin` and connect stay blocked
  ([unknowns](unknowns.md)).
- **Cross-version evidence covers 21 topics only**: certificate root, framing,
  HTTP chunking, integer and node encoding, Noise, socket, and registration
  requests, token and salt. These are the topics in the
  [37.70 → 37.71 core diff](apk/37.70-to-37.71-core-diff.json). Every other
  topic is 2.26.37.71-only, so for those a later release has no retained
  comparison point. A changed DEX hash still would not prove a protocol change,
  and a self-diff proves only plumbing.
- **78 of the 142 library files are cited by retained topics; 64 are not** (84 cited files in total, counting CLI files). The uncited
  list includes files whose evidence lives elsewhere (for example `quotes.rs`,
  `image_upload.rs`, `login.rs` and the app-state modules cite APK classes in
  comments and in [messaging-transport](messaging-transport.md) and
  [chat-actions](chat-actions.md)), model/store/runtime code that implements
  local policy rather than a traced APK behaviour, and newer modules such as
  `kem_prekeys.rs` and `hybrid/bundle.rs` whose traces are retained as REA
  envelopes rather than bundle topics. No cited file is missing.

## How to extend coverage

With an APK available (not in a cloud container; see
[unknowns](unknowns.md#apk-access-in-cloud-sessions-2026-10-13)):

1. export the pinned 2.26.36.75 core topics with `apk-research-bundle` and a
   recipe, then `apk-research-diff` against the 37.70 core bundle;
2. for uncited files that implement traced behaviour, add their topics to the
   relevant recipe so `rust_files` names them;
3. for a new release, `apk-research-remap` the 37.71 recipes, export, diff and
   rerun this report.
