# MEX null serialization: APK call site plus pinned platform source

**Confirmed static:** WhatsApp2.26.43.72 code264307238, SHA256 `887a6f94f6614791cfa845fe0b9990c064326d8b89cd71d81e817fc9fd530c2e`. Existing complete [0mF constructor](../2.26.43.72-mex-server-jid-equality/envelope-request.txt) calls query.getQueryParams().Axc(), passes the returned Map into org.json.JSONObject(Map), puts it under variables in another JSONObject, then calls toString. Existing [0j3 operation](../2.26.43.72-prekey-lid-mex-operation/iq-handle.txt) retains0mF and sends its constructed stanza on the non-Pando branch. Pando instead receives the typed query through Mja.ARN; this finding does not establish Pando serialization.

**Confirmed platform source, not an observed device runtime:** retained unmodified AOSP libcore sources are from android-16.0.0_r1 commit fff4fcc0cf7f080cf2511cbb57561482b13b218f. They carry their original Apache2.0 headers. provenance.json pins URLs; checksums.json binds every other file. This is source inspection, not REA runtime evidence or execution of Android code.

JSONObject.java lines138..152: Map constructor directly stores wrap(entry.getValue()) for every key. Lines800 onward: wrap(null) returns JSONObject.NULL; Collection wraps to JSONArray and Map recursively to JSONObject. JSONArray.java lines71..78 wraps each collection entry. JSONObject.writeTo lines731..737 emits every stored key through JSONStringer.value; JSONStringer.java lines235..265 recursively emits containers and renders the null sentinel as null. JSONObject.put(name,Object) lines267..278 separately removes an entry when given Java null. That put removal rule does not apply to null values traversed by the Map constructor.

The retained [GraphQlCallInput conversion](../2.26.43.72-usync-mex-variables/serialization.txt) converts Nha to nested TreeMaps and Nhb to lists, preserving stored null map values. For the selected cached-device builder, [HSo gates](../2.26.43.72-usync-mex-device-cache/README.md) initialize expected_timestamp/hash/timestamp to null then overwrite applicable entries. Under this pinned platform implementation, a present devices object retains timestamp:null and/or expected_timestamp:null when their comparison gates skip the overwrite; actual positive timestamp values remain decimal strings. More precisely: timestamp is null when cached timestamp<=0; expected_timestamp is null unless cached timestamp>0 AND expected>cached. Hash is the nonempty string required by the outer device-object gate. Do not omit the null entries merely because the general JSONObject.put null rule removes keys. Do not invent the entire devices object when its outer gate fails. Conditional include_* fields remain absent when their setters were skipped; null preservation does not manufacture absent keys.

**Inference / scope:** combining the APK call site with this platform implementation predicts explicit cached timestamp nulls on the selected JSON/non-Pando route. No actual handset platform build, OEM substitution/classloader behavior or live request was inspected. An APK method-body query for Lorg/json/JSONObject; returned no bodies; that bounded negative search does not prove runtime class identity. Exact null behavior for Pando remains unknown. This narrows the previous blanket serializer gap to a platform-qualified prediction; it is not a universal wire-null requirement.

Reproduce from repo root:
```sh
APK=../android-lab/apks/WhatsApp.1.apk
target/debug/xtask apk-smali "$APK" --class 'LX/0mF;' --method '<init>' --signatures --exceptions
target/debug/xtask apk-smali "$APK" --class 'Lorg/json/JSONObject;' --signatures --exceptions
```
To retrieve platform source, use each exact URL in provenance.json, decode the response with Python base64.b64decode, and compare SHA256/bytes with checksums.json. Resolve the reference tag with https://android.googlesource.com/platform/libcore/+/refs/tags/android-16.0.0_r1?format=JSON (strip the anti-XSSI first line); the commit must match provenance.json. No tests mirroring a serializer were added and no runtime UsyncQuery implementation was introduced. Cache authority, complete variables, response adoption and account restrictions remain separate obligations. No live operation.
