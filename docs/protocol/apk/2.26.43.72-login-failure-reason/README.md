# Initial login failure reason is required Java int

**Confirmed static**, WhatsApp2.26.43.72/code264307238, APK SHA-256
`887a6f94f6614791cfa845fe0b9990c064326d8b89cd71d81e817fc9fd530c2e`.
Baseline `41f5204a`. Offline xtask DEX fallback, not REA provider evidence;
[known provider failure](../2.26.43.72-retry-key-envelope-bytes/rea-provider-attempt.json).
No target execution or live request.

The retained [0ZJ.A13](../2.26.43.72-login-success-reader/login-reader.txt)
checks failure at03de and calls0Tp.A04("reason") at03f2 before its failure
mapping. [A04](required-integer.txt) obtains required text through
[A0L](required-text.txt); missing text throwsLIL. It then calls
[A06](integer-parser.txt), which invokes Integer.parseInt and converts
NumberFormatException intoLIL. Malformed, absent and out-of-signed-i32 reasons
therefore do not reach this reader's native reason-specific failure branches.
This does not establish every outer catch/reconnect/reservation policy or the
long-running reader's independent failure path. Native diagnostics concatenate
input; Rust retains fixed redacted errors instead.

**Confirmed local defect/fixed offline:** the initial Rust result setter accepted
any failure root as refused, silently making missing/malformed reasons code=null.
It also limited text to five bytes and parsed unsigned u32, losing Java-valid
leading-zero, BMP decimal-digit and longer signed-i32 values. The baseline owned
capture/settlement regression failed because a missing reason became
Authentication(None) instead of preserving the original uncertain outcome.

The setter now requires text parsed by the existing Java decimal parser and
bounded to i32 before settlement. Malformed values return fixed non-recoverable
InvalidInput(connection), preserving earlier reply capture and reservation.
A valid failure still becomes refused; no retry or refusal reset is introduced.
Error::Authentication.code and stored code remain Option<u32>, so negative valid
native values are still represented as null/None (known local representation
limit), while nonnegative i32 values retain their number. This patch does not
invent a negative-code mapping or native meaning for arbitrary numeric values.
Success ignores this failure-only attribute. No wire construction changes.

Owned real-store regression covers missing/empty/nonnumeric/positive and negative
overflow/padded-whitespace/non-UTF8/JID reasons. It verifies fixed terminal error,
unchanged account/checkpoint/pin/session/outbox snapshots and journal after durable
capture; reopen retains uncertainty and blocks a fresh reservation. Snapshot scope
is the synthetic test store, not arbitrary production history. Valid controls
405,+403,000000403,fullwidth403,i32::MAX and i32::MIN check authentication outcome
and stored refused/code values. Existing malformed identity and stale reservation
controls remain. No fresh account, identity rotation or live account operation.
